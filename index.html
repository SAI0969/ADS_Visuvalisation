⚖️ AVL Tree Fundamentals & Rotations

Invented in 1962 by Adelson-Velsky and Landis, the AVL tree strictly bounds height by guaranteeing that for every node $v$:

Balance Factor: BF(v) = Height(Left Subtree) − Height(Right Subtree) ∈ {-1, 0, +1}

Strict Height Upper Bound Theorem: $h < 1.4404 \log_2(N + 2) - 0.328 \approx O(\log N)$.

4 Rebalancing Rotations:

LL: Single Right Rotation BF = +2, Child ≥ 0

Left-heavy node with left-heavy child. Rotates right around unbalanced node.

RR: Single Left Rotation BF = -2, Child ≤ 0

Right-heavy node with right-heavy child. Rotates left around unbalanced node.

LR: Double Rotation Left then Right

Zigzag left-right: Left rotate child first, then Right rotate parent.

RL: Double Rotation Right then Left

Zigzag right-left: Right rotate child first, then Left rotate parent.

🔴 Red-Black Tree Properties & Invariants

Introduced by Rudolf Bayer (1972) and refined by Guibas & Sedgewick (1978), Red-Black trees are self-balancing BSTs widely used in production runtimes (C++ std::map, Java TreeMap, Linux Completely Fair Scheduler).

The 5 Fundamental Properties:

  • Property 1: Every node is colored either RED or BLACK.
  • Property 2: The root is always BLACK.
  • Property 3: All NIL leaf nodes are BLACK.
  • Property 4: If a node is RED, both of its children must be BLACK (no two consecutive reds).
  • Property 5 (Black-Height): Every path from a given node to any of its descendant NIL leaves contains the exact same number of BLACK nodes.

Height Guarantee: Height $h \le 2 \log_2(N + 1) = O(\log N)$. Insertion requires at most 2 rotations; deletion requires at most 3 rotations!

🌳 B-Tree Fundamentals & Invariants (Order M)

Designed for block storage, filesystems, and databases where disk I/O dominates latency.

  • Every internal node contains at most $M$ children and at most $M - 1$ keys.
  • Every internal node (except root) contains at least $\lceil M / 2 \rceil$ children and $\lceil M / 2 \rceil - 1$ keys.
  • All leaf nodes are strictly placed at the exact same depth.
  • Node Split: Overfilled node splits at median; median is pushed up to parent.
  • Borrow & Merge: Underfilled nodes borrow from siblings or merge with parent key pull-down.

📑 B+ Tree Architecture & Sequential Leaf Chaining

The gold standard index structure for relational database engines (PostgreSQL, MySQL InnoDB, SQLite).

Key Differences from B-Tree:

  • Data Resides Exclusively in Leaves: Internal nodes hold only routing keys and pointers, maximizing fanout and cache line efficiency.
  • Singly/Doubly Linked Leaves: All leaf nodes are linked horizontally. Once the lower bound is located in $O(\log_M N)$ time, range scans execute sequentially in linear $O(K)$ time along the linked chain without traversing back up!
  • Copy-Up Splits: When a leaf splits, its median key is copied up to the parent while remaining inside the right leaf.

🔤 Trie (Prefix Tree) Data Structure

An ordered tree data structure used to store dynamic sets of strings where keys are usually strings.

  • Prefix Sharing: All descendants of a node share a common string prefix.
  • Time Complexity: Lookup, insertion, and deletion depend strictly on string length $L$: $O(L)$, completely independent of the number of words $N$ stored!
  • Ideal Applications: Autocomplete search suggestions, spell checkers, IP routing longest-prefix match.

📏 Segment Tree for Range Queries

A binary tree used for storing intervals or segments, allowing fast querying of which stored segments contain a given point, or range queries over arrays.

  • Structure: Leaf nodes represent array indices $[i..i]$; internal nodes represent range $[L..R]$ with aggregate sum, minimum, or maximum.
  • Range Sum Query (RSQ): Solved in $O(\log N)$ time by decomposing any arbitrary query interval $[qL..qR]$ into at most $O(\log N)$ canonical segments.
  • Point Update: Single element update takes $O(\log N)$ by updating leaf and backtracking to recalculate ancestor segment sums.

📜 Suffix Tree for String Analysis

A compressed trie containing all suffixes of a given text string $S\$$.

  • Edge Compression: Non-branching paths are compressed into substring edges, ensuring at most $2N$ nodes and $O(N)$ linear space.
  • Pattern Search: Determines if a pattern $P$ of length $M$ occurs in text $T$ of length $N$ in $O(M)$ time, completely independent of text length $N$!
  • Genomics & Bioinformatics: DNA motif matching, longest common substring, and genome assembly.

🎯 2D K-D Tree (Spatial Partitioning)

A space-partitioning binary tree for organizing points in a $k$-dimensional space (here $k = 2$).

  • Alternating Cutting Planes: Level 0 splits on $X$-axis; Level 1 splits on $Y$-axis; Level 2 splits on $X$-axis, etc.
  • Nearest Neighbor (NN) Search: Traverses down to find the closest leaf, then backtracks with geometric pruning: if the distance to the splitting plane is greater than the current best distance, the entire opposite branch is pruned!
  • Complexity: Average search is $O(\log N)$; worst case 2D range search is $O(\sqrt{N})$.

🧵 Threaded Binary Tree (O(1) Auxiliary Space Traversal)

In an ordinary binary tree of $N$ nodes, $N + 1$ pointers are NULL. A Threaded Binary Tree puts these wasted null pointers to work!

  • Threads: A null left pointer points to the in-order predecessor; a null right pointer points to the in-order successor.
  • Stackless Traversal: Traverses the entire tree in sorted order in $O(N)$ time and $O(1)$ auxiliary space without any recursion or stack overhead!
  • Embedded Hardware: Vital for microcontrollers, embedded systems, and real-time devices with strict call stack limits.
