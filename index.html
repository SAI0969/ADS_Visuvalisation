📖 1. Overview
Invented in 1962 by Soviet mathematicians Georgy Adelson-Velsky and Evgenii Landis, the AVL tree is the first self-balancing binary search tree ever created. Its primary purpose is to guarantee that the height of the tree strictly remains O(log N), preventing worst-case O(N) degeneration of standard BSTs.
⚖️ 2. Properties & Rules
  • Balance Factor Invariant: For every node v:
    BF(v) = Height(Left) − Height(Right) ∈ {-1, 0, +1}
  • Strict Height Upper Bound: Maximum height is strictly bounded by h < 1.44 log₂(N + 2) − 0.328 ≈ 1.44 log₂ N.
  • Recursive Subtrees: Every subtree of an AVL tree is itself an AVL tree.
⚙️ 3. Operations (Insert, Delete, Search)
  • Search: Identical to standard BST traversal in O(log N) time.
  • Insert: Insert node as a leaf following BST ordering, then backtrack to root updating heights and executing rotations on any unbalanced node.
  • Delete: Standard BST deletion (leaf, single child, or two children with in-order successor), followed by backtracking and potentially cascading rotations up to root.
🎬 4. Animation Walkthrough (Example: Inserting 50 into AVL)
  1. Insert 50 using BST insertion rules: Compare 50 with nodes starting from root, traversing right until an empty leaf position is reached.
  2. Calculate the balance factor: Backtrack upward from the inserted node, recalculating BF(v) = Height(Left) - Height(Right).
  3. Detect whether the tree is unbalanced: Identify if any ancestor node A violates the invariant (|BF(A)| > 1).
  4. Identify the rotation required:
    • LL (Left-Left): Single Right Rotation (Parent BF = +2, Child BF ≥ 0)
    • RR (Right-Right): Single Left Rotation (Parent BF = -2, Child BF ≤ 0)
    • LR (Left-Right): Double Rotation: Left rotate child, then Right rotate parent
    • RL (Right-Left): Double Rotation: Right rotate child, then Left rotate parent
  5. Perform the rotation: Pivot node pointers are updated and subtree heights recalculated.
  6. Display the final balanced tree: All balance factors satisfy |BF| ≤ 1, restoring O(log N) optimality!
⏱️ 5. Complexity Analysis
OperationBestAverageWorst
SearchO(1)O(log N)O(log N)
InsertO(1)O(log N)O(log N)
DeleteO(1)O(log N)O(log N)
SpaceO(N) data + O(log N) recursion stack
📝 6. Solved Example
Sequence: Insert 30, 20, 10 into an empty tree:
  • Insert 30 (Root, BF = 0).
  • Insert 20 (Left of 30, 30's BF = +1).
  • Insert 10 (Left of 20, 30's BF = +2). Unbalance detected at node 30!
  • Child 20 has BF = +1 (Left-Left case).
  • Action: Perform Single Right Rotation at 30. Node 20 becomes new root, 10 left child, 30 right child. Tree is perfectly balanced!
🚀 7. Real-World Applications
Because AVL trees maintain strict height guarantees (flatter than Red-Black trees), they are optimal for read-heavy in-memory workloads where lookups drastically outnumber updates:
  • In-memory database index lookups and symbol tables for compilers.
  • High-frequency trading price-level books and order routing tables.
  • Operating system virtual memory interval mapping (macOS Mach kernel VM ranges).
📖 1. Overview
Introduced by Rudolf Bayer (1972) and refined by Guibas & Sedgewick (1978), Red-Black Trees are self-balancing BSTs that use an extra color bit per node to maintain balance with significantly fewer rotations during modifications than AVL trees.
⚖️ 2. Properties (5 Golden Invariants)
  1. Every node is colored either RED or BLACK.
  2. The root is always BLACK.
  3. All NIL leaf nodes are BLACK.
  4. If a node is RED, both children must be BLACK (No two consecutive reds).
  5. Black-Height: Every path from a node to any descendant NIL leaf contains identical black nodes.
⚙️ 3. Operations
  • Insert: Insert new node colored RED. If parent is Red, resolve violations using at most 2 rotations.
  • Delete: Remove node; if a black node is removed, handle double-black with at most 3 rotations.
  • Search: Standard BST lookup in O(log N) time.
🎬 4. Animation Walkthrough (Double-Red Resolution)
  1. Insert key colored RED into BST leaf position.
  2. If parent is Black: Tree is valid; operation complete.
  3. If parent is Red: Check color of Uncle node:
    • Case 1 (Uncle is Red): Recolor parent and uncle to BLACK, grandparent to RED. Backtrack to grandparent.
    • Case 2 (Uncle is Black, Zigzag): Rotate child to align with parent into a straight line.
    • Case 3 (Uncle is Black, Straight): Rotate grandparent, swap colors of parent and grandparent. Tree is balanced!
  4. Always force root color to BLACK at termination.
⏱️ 5. Complexity Analysis
OperationAverageWorstRotations
SearchO(log N)O(log N)0
InsertO(log N)O(log N)≤ 2
DeleteO(log N)O(log N)≤ 3
📝 6. Solved Example
Sequence: Insert 10, 20, 30:
  • Insert 10: Root is colored BLACK.
  • Insert 20: Right child of 10, colored RED. No violation.
  • Insert 30: Right child of 20, colored RED. Double Red violation between 20 and 30!
  • Uncle of 30 is NIL (Black). Straight line RR case.
  • Action: Left rotate around 10. 20 becomes Black root; 10 and 30 become Red children. Black-height is 2 everywhere!
🚀 7. Real-World Applications
The industry standard for write-heavy general-purpose collections:
  • Linux Kernel: Completely Fair Scheduler (CFS) prioritizes tasks using a Red-Black tree; epoll tracking file descriptors.
  • Language Standard Libraries: C++ std::map, std::set; Java TreeMap, TreeSet.
📖 1. Overview
Invented by Rudolf Bayer & Edward McCreight (1970), the B-Tree is a self-balancing search tree tailored for storage systems where reading and writing large blocks of memory (disk pages) dominates computational latency.
⚖️ 2. Invariants (Order M)
  • Every node has at most M children and at most M − 1 keys.
  • Every internal node (except root) has at least ⌈M / 2⌉ children and ⌈M / 2⌉ − 1 keys.
  • Strict Leaf Invariant: All leaf nodes reside at the exact same depth.
⚙️ 3. Operations
  • Search: Multi-way branching down through ordered keys in O(logM N) steps.
  • Insert: Insert key in sorted order in leaf. If keys exceed M − 1, split at median key and push median up to parent.
  • Delete: Borrow from sibling or merge with sibling if node becomes underfilled (< ⌈M / 2⌉ − 1 keys).
🎬 4. Animation Walkthrough (Node Splitting)
  1. Traverse multi-way keys from root to locate appropriate leaf.
  2. Insert key into leaf keeping keys sorted.
  3. If number of keys exceeds maximum capacity (M − 1):
  4. Locate the median key at index ⌊M / 2⌋.
  5. Split node into left half and right half, pushing median key into parent node.
  6. If parent overflows, cascade split recursively upward to root.
⏱️ 5. Complexity Analysis
OperationComplexityI/O Complexity
SearchO(log_M N)O(log_B N) disk reads
InsertO(M log_M N)O(log_B N) disk writes
DeleteO(M log_M N)O(log_B N)
📝 6. Solved Example
Order M = 3 (2-3 Tree): Max 2 keys per node:
  • Insert 10: Root [10]
  • Insert 20: Root [10, 20] (Full)
  • Insert 30: Node overflows [10, 20, 30]!
  • Median key 20 is pushed up to new root [20].
  • Left child [10], Right child [30]. Height increases uniformly by 1.
🚀 7. Real-World Applications
Primary data structure for traditional filesystems: NTFS, HFS+, ext4, and disk paging managers.
📖 1. Overview
The B+ Tree is the foundation of modern relational database storage engines. Unlike standard B-trees, all user record keys are stored exclusively in leaf nodes, while internal nodes store routing keys.
⚖️ 2. Properties & Leaf Chaining
  • Linked Leaf Chain: Every leaf node points to the next adjacent leaf node horizontally.
  • Maximum Fanout: Internal nodes hold no record payload, allowing thousands of routing pointers per 4KB/8KB disk block.
  • Copy-Up Splits: Median key is copied up to parent during leaf splits while remaining in leaf.
⚙️ 3. Operations (Point & Range Queries)
  • Point Search: Navigates internal routing keys to leaf in O(logM N).
  • Range Scan [Min..Max]: Find lower bound leaf in O(logM N), then stream sequentially along horizontal leaf pointers in O(K) time!
🎬 4. Animation Walkthrough (Range Query Scan)
  1. User specifies Range bounds [Min..Max].
  2. Traverse from root down to the first leaf containing key ≥ Min.
  3. Collect matching keys from current leaf block.
  4. Follow horizontal nextLeaf thread pointer directly to adjacent right sibling.
  5. Continue streaming until keys exceed Max without ever traversing back up internal nodes!
⏱️ 5. Complexity Analysis
OperationTime ComplexityNotes
Point SearchO(log_M N)Exact leaf lookup
Range QueryO(log_M N + K)K is number of matches
Insert / DeleteO(M log_M N)With copy-up splits
📝 6. Solved Example
Query Range [6..20]:
  • Search routing keys for lower bound 6 -> Lands on Leaf [5, 6, 7].
  • Matches 6 and 7. Follows horizontal leaf link to Leaf [10, 12].
  • Matches 10 and 12. Follows leaf link to Leaf [20, 30].
  • Matches 20. Next key 30 > 20 -> Range scan terminates! Result: [6, 7, 10, 12, 20].
🚀 7. Real-World Applications
Primary index architecture for: PostgreSQL, MySQL InnoDB, SQLite, Oracle, and Apple APFS.
📖 1. Overview
A Trie (Prefix Tree) is a tree data structure used to store associative arrays where keys are strings. All descendants of a node share a common string prefix.
⚖️ 2. Properties
  • Root represents the empty string.
  • Key length L governs lookup time, completely independent of total words N stored!
  • Nodes contain terminal end-of-word markers.
⚙️ 3. Operations
  • Insert Word: Walk existing prefix characters, allocate nodes for new characters, mark final character as terminal.
  • Search Word: Traverse character edges. Found if path exists and terminal is true.
  • StartsWith: Prefix query returns true if prefix path exists.
🎬 4. Animation Walkthrough (Word Insertion)
  1. Start at Root for word W = c₁ c₂ … cL.
  2. For character ci, check if an outgoing edge labeled ci exists.
  3. If missing: allocate a new child node labeled ci.
  4. Advance current pointer to the child node.
  5. At terminal character cL, toggle isEndOfWord = true (highlighted green).
⏱️ 5. Complexity Analysis
OperationTime ComplexitySpace Complexity
InsertO(L)O(Σ · L · N)
SearchO(L)L = string length
StartsWithO(P)P = prefix length
📝 6. Solved Example
Words: "cat", "car", "cart":
  • "cat" creates path: Root -> 'c' -> 'a' -> 't' (terminal).
  • "car" shares prefix "ca", branches at 'a' -> 'r' (terminal).
  • "cart" extends from 'r' -> 't' (terminal). Optimal prefix sharing!
🚀 7. Real-World Applications
Search engine autocomplete suggestions, spell check dictionaries, and IP routing longest prefix matching.
📖 1. Overview
A Segment Tree is a binary tree designed for fast range queries (e.g. sum, min, max) and point updates over an array in logarithmic O(log N) time.
⚖️ 2. Properties
  • Root node represents the entire array interval [0..N − 1].
  • Leaf nodes represent individual elements [i..i].
  • Internal nodes store aggregate sums of interval [L..R]. Height is strictly ⌈log₂ N⌉.
⚙️ 3. Operations
  • Range Query [qL..qR]: Decomposes arbitrary range into at most O(log N) canonical segments.
  • Point Update (Index, Value): Updates leaf element and backtracks up ancestor path recalculating aggregate sums.
🎬 4. Animation Walkthrough (Range Sum Query)
  1. Begin at root segment [0..N − 1] for query range [qL..qR].
  2. Total Overlap: If current segment [L..R] lies completely inside [qL..qR], return stored sum immediately.
  3. No Overlap: If current segment lies completely outside, return 0 (prune subtree).
  4. Partial Overlap: Recursively query left child [L..mid] and right child [mid + 1..R].
  5. Sum results from children and return.
⏱️ 5. Complexity Analysis
OperationTimeSpace
Build TreeO(N)O(4N)
Range QueryO(log N)O(log N) stack
Point UpdateO(log N)O(log N) stack
📝 6. Solved Example
Array: [1, 3, 5, 7, 9, 11], Query [1..4]:
  • Root [0..5] (Sum 36) has partial overlap -> Split.
  • Left child [0..2] overlaps partially -> [0..0] pruned, [1..2] (Sum 8) accepted.
  • Right child [3..5] overlaps partially -> [3..4] (Sum 16) accepted, [5..5] pruned.
  • Total: 8 + 16 = 24. Only 4 node visits instead of scanning whole array!
🚀 7. Real-World Applications
Stock market trading ticker interval volume/price queries, computational geometry window queries, competitive programming.
📖 1. Overview
A Suffix Tree is a compressed trie containing all suffixes of a string T (terminated with sentinel character '$'). Enables substring pattern matching in time proportional strictly to pattern length O(M).
⚖️ 2. Properties
  • Contains exactly N leaves for text of length N.
  • Edge compression ensures at most 2N nodes and linear O(N) space.
⚙️ 3. Operations
  • Build: Linear O(N) construction via Ukkonen's algorithm.
  • Pattern Match: Search pattern P in O(M) time regardless of document size N.
🎬 4. Animation Walkthrough
  1. Start at root with pattern P.
  2. Find outgoing edge whose label starts with P[0].
  3. Match characters along edge label.
  4. If pattern matches completely, occurrences are found in subtree leaves!
⏱️ 5. Complexity Analysis
OperationTimeSpace
Build (Ukkonen)O(N)O(N)
Pattern SearchO(M)M = pattern length
📝 6. Solved Example
Text "banana$": Suffixes include "banana$", "anana$", "nana$", "ana$", "na$", "a$", and sentinel "$". Searching "ana" immediately follows edge "ana" to leaf indices [1, 3]!
🚀 7. Real-World Applications
Genomic DNA sequence alignment (BLAST), plagiarism detection, and data compression.
📖 1. Overview
A 2D K-D Tree partitions 2-dimensional space into hierarchical bounding regions by alternating splitting axes (X and Y) at each depth level.
⚖️ 2. Properties
  • Level 0, 2, 4 splits along X-coordinate (vertical cutting plane).
  • Level 1, 3, 5 splits along Y-coordinate (horizontal cutting plane).
  • Enables geometric branch pruning for Nearest Neighbor (NN) search.
⚙️ 3. Operations
  • Insert Point (X, Y): Descends alternating X / Y comparison.
  • Nearest Neighbor: Traverses to leaf, then backtracks with hypersphere distance bounding to prune entire subtrees.
🎬 4. Animation Walkthrough (Nearest Neighbor Pruning)
  1. Inspect target point coordinates (Tx, Ty).
  2. Descend to leaf comparing target coordinate against current splitting axis.
  3. Set initial best distance R to leaf point distance.
  4. Backtrack up: calculate perpendicular distance from target to cutting plane.
  5. If cutting plane distance ≥ R: Prune entire opposite subtree!
  6. Otherwise: search opposite subtree.
⏱️ 5. Complexity Analysis
OperationAverageWorst Case
InsertO(log N)O(N)
Nearest NeighborO(log N)O(√N)
📝 6. Solved Example
Target (15, 25) with root (30, 40) splitting on X. Target has X = 15 < 30, searches left branch. When backtracking, distance to X = 30 is 15. If best distance is 8, the entire right branch is pruned without checking!
🚀 7. Real-World Applications
Robotics collision avoidance, computer graphics ray tracing photon mapping, GPS nearest location queries.
📖 1. Overview
A Threaded Binary Search Tree replaces wasted null leaf pointers with direct threads pointing to in-order predecessors and successors.
⚖️ 2. Properties
  • In a standard tree of N nodes, N + 1 pointers are NULL. Threading puts these pointers to work.
  • Enables full in-order traversal in O(N) time and strictly O(1) auxiliary space (Zero stack or recursion!).
⚙️ 3. Operations
  • Threaded Traversal: If right pointer is a thread, jump directly to successor; otherwise move right and find leftmost child.
🎬 4. Animation Walkthrough
  1. Find leftmost node in tree.
  2. Visit node.
  3. If right pointer is a thread: follow thread directly to successor!
  4. If right pointer is a child: navigate right, then descend left to minimum.
  5. Zero call stack frames allocated!
⏱️ 5. Complexity Analysis
OperationTimeAuxiliary Space
TraversalO(N)O(1) Zero stack!
Insert / SearchO(log N)O(1)
📝 6. Solved Example
Tree with root 20, left 10, right 30. Leaf 10 has a right thread pointing directly to 20. Traversal visits 10, follows thread to 20, then moves to 30 with zero stack overhead!
🚀 7. Real-World Applications
Embedded systems, microcontrollers, real-time operating systems (RTOS) with tiny call stack budgets.
