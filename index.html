⚖️ AVL Tree Fundamentals & Balance Invariants

An AVL Tree (invented in 1962 by Soviet mathematicians Georgy Adelson-Velsky and Evgenii Landis) is the first self-balancing binary search tree in computer science history. Ordinary BSTs can degrade into $O(N)$ skewed chains upon inserting sorted data; AVL trees eliminate this by strictly enforcing balance invariants on every update.

1. Balance Factor (BF) Definition

For every node $v$ in an AVL tree, its Balance Factor is mathematically defined as:

Balance Factor: BF(v) = Height(Left Subtree) − Height(Right Subtree)

A node is valid and balanced if and only if:
BF(v) ∈ {-1, 0, +1}

  • BF = 0: Perfect balance; left and right subtrees have equal height.
  • BF = +1: Left-heavy; left subtree is 1 level taller than right.
  • BF = -1: Right-heavy; right subtree is 1 level taller than left.
  • |BF| ≥ 2: Violation! Requires immediate constant-time $O(1)$ rotation.

2. Mathematical Height Bound Theorem

Let $N(h)$ be the minimum number of nodes in an AVL tree of height $h$. The recurrence is:

N(h) = 1 + N(h - 1) + N(h - 2)   (where N(0) = 0, N(1) = 1)

Since $N(h) = F_{h+2} - 1$ (where $F_k$ is the $k$-th Fibonacci number), solving the golden ratio $\phi = \frac{1 + \sqrt{5}}{2} \approx 1.618$ gives the upper bound on height:

h < 1.4404 · log₂(N + 2) − 0.328  ⇒  h = O(log N)

This guarantees that search, insertion, and deletion are always strictly $O(\log N)$.

🔄 The 4 Rebalancing Rotations

When an insertion or deletion pushes a node's Balance Factor to $+2$ or $-2$, the tree performs one of four canonical rotations. Rotations execute in $O(1)$ time by adjusting a few pointers without altering the in-order sorting invariant.

1. Left-Left (LL) Case Single Right Rotation

Triggered when node $z$ has BF = +2 and left child $y$ has BF ≥ 0.

[z] (+2) [y] (0) / \ / \ [y] T4 ===> [x] [z] / \ / \ / \ [x] T3 T1 T2 T3 T4 / \ T1 T2
2. Right-Right (RR) Case Single Left Rotation

Triggered when node $z$ has BF = -2 and right child $y$ has BF ≤ 0.

[z] (-2) [y] (0) / \ / \ T1 [y] ===> [z] [x] / \ / \ / \ T2 [x] T1 T2 T3 T4 / \ T3 T4
3. Left-Right (LR) Case Double: Left then Right

Triggered when node $z$ has BF = +2 and left child $y$ has BF = -1 (zigzag).

[z] (+2) [z] (+2) [x] (0) / \ / \ / \ [y] T4 ==Left=> [x] T4 ==Right=> [y] [z] / \ / \ / \ / \ T1 [x] [y] T3 T1 T2 T3 T4 / \ / \ T2 T3 T1 T2
4. Right-Left (RL) Case Double: Right then Left

Triggered when node $z$ has BF = -2 and right child $y$ has BF = +1 (zigzag).

[z] (-2) [z] (-2) [x] (0) / \ / \ / \ T1 [y] ==Right=> T1 [x] ==Left=> [z] [y] / \ / \ / \ / \ [x] T4 T2 [y] T1 T2 T3 T4 / \ / \ T2 T3 T3 T4

🌳 B-Tree Fundamentals & Invariants

A B-Tree (invented by Rudolf Bayer and Edward M. McCreight in 1972) is a self-balancing, multi-way search tree specifically designed for storage systems, databases (PostgreSQL, MySQL InnoDB), and filesystems (ext4, NTFS, Btrfs) where reading large blocks from disk or flash memory dominates performance.

Fundamental Invariants of Order M:

  • Order M: Every internal node has at most $M$ children.
  • Non-root Branching: Every non-root node has at least $\lceil M / 2 \rceil$ children.
  • Key Capacity: Every node contains between $\lceil M / 2 \rceil - 1$ and $M - 1$ keys. (The root may hold as few as 1 key).
  • Strict Leaf Alignment: All leaves appear at the exact same depth ($h$).
  • Internal Pointers: A node with $k$ keys contains exactly $k + 1$ child pointers separating key ranges.

Overflow & Underflow Operations:

  • Node Splitting: When insertion causes keys to exceed $M - 1$, the node splits at the median key. The median is promoted to the parent, creating two sibling nodes.
  • Borrowing (Rotation): If a deletion causes a node to fall below $\lceil M / 2 \rceil - 1$ keys, it first attempts to borrow a key from its left or right sibling via parent rotation.
  • Node Merging: If neither sibling has spare keys, the node merges with a sibling and pulls down the separating key from the parent. If the parent root is emptied, tree height decreases by 1.

⏱️ Comprehensive Time & Space Complexity Analysis

Comparison of theoretical performance guarantees between AVL Trees and B-Trees across all primary operations.

Operation AVL Tree (Binary) B-Tree of Order M Why / Mechanism
Search (Lookup) O(log N) O(log_M N) AVL does at most $1.44 \log_2 N$ pointer hops; B-Tree does $\log_{M/2} N$ node reads with binary search inside each node.
Insertion O(log N) O(M · log_M N) AVL requires $O(\log N)$ traversal + at most 1 single/double rotation. B-Tree splits nodes upwards if overflowing.
Deletion O(log N) O(M · log_M N) AVL does $O(\log N)$ search + predecessor swap + up to $O(\log N)$ cascading rotations. B-Tree borrows or merges underflowing nodes.
Tree Height (h) h ≤ 1.44 log₂ N h ≤ log_{⌈M/2⌉}((N+1)/2) + 1 B-Trees are extremely shallow (height 3 to 4 can hold millions of keys), minimizing expensive disk I/O.
Rebalance Cost (Insert) O(1) (at most 2 rotations) O(1) amortized A single AVL rotation restores subtree height to its pre-insert value, preventing further propagation.
Rebalance Cost (Delete) O(log N) (cascading) O(log_M N) Deletion rebalances can propagate all the way up to the root in both trees.
Auxiliary Space O(log N) stack O(log_M N) stack Call stack for recursion or search traversal path.
